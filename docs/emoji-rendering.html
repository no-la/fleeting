FLEETING / 描画の解説

絵柄はそのまま。
拡大する経路を変える。

今回使ったのは、端末の絵文字を160pxのフォントサイズで一度画像にし、その画像を補間して拡大する方法です。SVGへの変換やAIによる高解像度化はしていません。

1. 変更したのは、この3段階

以前は大きなフォントサイズを指定して、絵文字を直接 fillText() で描いていました。変更後は、160pxを超える絵文字だけ次の経路に通します。

01 / 文字 → 画像160pxで描画

Apple Color Emojiなど、端末の絵文字フォントを小さな作業用Canvasに描きます。

fillText()
→
02 / サイズを計算必要な倍率を求める

目標のフォントサイズを160で割り、画像の幅・高さ・位置に同じ倍率を掛けます。

目標サイズ ÷ 160
→
03 / 画像 → キャンバス補間して拡大

画像の拡大に高品質補間を指定し、編集用Canvasへ合成します。

drawImage()
例：800pxで描きたい → 800 ÷ 160 = 5倍

160pxはフォントサイズです。作業用画像が160×160ピクセルという意味ではありません。実際の画像サイズは絵文字の描画範囲に合わせます。

2. 「補間」は何をしている？

拡大先の画素に、周囲の元画素の色を使って色を割り当てます。色の境目を滑らかにつなぐため、輪郭のギザギザが目立ちにくくなります。

補間方式の詳細はブラウザ任せです。 コードでは imageSmoothingQuality = "high" を指定していますが、「必ずバイキュービック」「必ずLanczos」など、特定の計算方式を指定したわけではありません。

3. この端末で比べる

左は大きな文字サイズで直接描画。右は今回の方法です。両方とも1080×1080pxのCanvasを同じ大きさで表示しています。

表示は端末・OS・ブラウザで変わります。iPhoneではAppleの絵文字、他の環境ではその端末の絵文字を使います。小さい画面では差が見えにくい場合があります。

4. 実装上の工夫

絵文字を途中で分割しない

Intl.Segmenter で見た目の1文字ごとに分けます。👩‍💻のような結合絵文字、国旗、肌色付き絵文字をひとまとまりとして処理します。

描画範囲と基準位置を記録

measureText() の実際の描画範囲に各辺2pxの余白を付けます。基準位置からのずれも保存し、文字と並べたときの位置を保ちます。

同じ絵文字の画像は再利用

作業用Canvasを最大128件保存。拡大・移動のたびに文字から描き直さず再利用します。満杯なら、最も古く登録したものから外します。

小さな絵文字は直接描画

160px以下では従来どおり描きます。補間経路を使うのは160pxを超える絵文字だけで、通常の文章は文字として描画します。

// 流れを示す抜粋。位置・描画範囲の処理は省略。
const baseSize = 160;
source.font = '160px "Apple Color Emoji", sans-serif';
source.fillText(emoji, x, y);

const scale = targetSize / baseSize;
output.imageSmoothingEnabled = true;
output.imageSmoothingQuality = "high";
output.drawImage(bitmap, x, y,
  bitmap.width * scale, bitmap.height * scale);

5. 改善できること・できないこと

改善するのは、拡大時の輪郭のザラつきです。 元の絵文字にない細部を作る処理ではないため、非常に大きくすると柔らかく、ぼやけて見えることがあります。

MacのChromiumでは、👩‍💻・😂・🇯🇵で改善を比較確認しました。また、fillText() に高品質補間を設定するだけでは、出力画素は変わりませんでした。文字描画から画像描画へ経路を切り替えることがポイントです。

160pxは今回の比較で良好だった実用値で、全OS共通の最適値ではありません。iPhone実機の効果と、当時のTwitterフリートが同じ手法を使っていたかは未確認です。出力PNGは引き続き1080×1920pxです。
